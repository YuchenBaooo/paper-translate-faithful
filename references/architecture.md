# 工作原理与工具分工

翻译、对象处理、排版、技术检查和真实审校各自留存证据。语言模型负责结合全篇语境翻译和审校；本地 Python 工具负责 PDF 的结构、字形、坐标、渲染和文件一致性，不直接调用翻译 API。

| 组件 | 作用 | 输出或门槛 |
|---|---|---|
| paperflow.py | 源文件冻结、稳定单元 ID、原位译文提交、回填与发布 | 哈希绑定、数字/保护片段/字体/保护区域检查 |
| readerflow.py | 在授权范围内按语义段落重排中文与原生数学对象 | 单元恰好一次、资产出现次数、字形与基线、越界/重叠/可读性审校 |
| vector_assets.py | 组合已经核对的矢量片段、提取嵌入字形实际轮廓 | 不猜测跨行公式的语义连接，记录裁切证据 |
| reference_rows.py | 从审过的列区域提出完整文献条目 | 续行、编号、裁切半行检查，输出待复核提案 |
| raster_label_patch.py | 用已核对 mask 恢复局部背景并填中文 | 科学内容保护、编辑区外像素检查、仍须看图 |
| pdf_compact.py | 可选字体子集化与文件压缩 | 限时 worker；逐页像素/文本/目录一致且更小才采用 |
| ocr_region.py | 无损裁图与本地 OCR 坐标转换 | OCR 是识别提案，不能自动批准 |
| babeldoc_bridge.py | 可选外部排版引擎捕获与回放 | 按 occurrence 绑定，拒绝错配和损坏占位符 |

所有工具以实际可用能力为准；无需同时启用全部路线。详细用法见 routes.md、job-format.md、reading-layout.md 和 reader-plan.md。完成脚本不等于科学语义准确，publish 始终要求真实审校记录。
