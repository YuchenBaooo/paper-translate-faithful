# 四条验收证据

1. **识别证据**：每页真实查看，原文字层/OCR 与原图对应；无漏页/错栏/漏字/混合行；所有可见图片文字和表格都登记。`extraction.pages` 覆盖所有实际页。低 OCR 置信度不是唯一异常，数字、负号、小数点和相似希腊字母必须看图。
2. **语义证据**：每个 occurrence ID 的源译对照。每项 `meaning/terminology/numbers/structure` 都需实际审查；检查否定、条件、比较方向、单位、因果、假设、证据强度和数据归属。段落断开时看相邻上下文。审校者身份和方法如实记录。
3. **视觉与可读性证据**：绑定确切候选 SHA-256；逐页对照，所有公式、图表、图内标签核对。`visual.pages` 覆盖整篇，任何待解决项不能填 pass。另查中文长空白、稀疏分布、异常行距、标点禁则、基线、公式编号净空、孤立标题、图注分离、作者简介碎片和文献失衡。原位模式也须看可读性，像素一致不能替代。阅读版允许已授权的位移，但须验证源单元与原数学资产无漏损，不能套原坐标一致检查。自动化像素检查只覆盖已登记保护区和写区之外，不能证明被登记为写区的地方没有删错内容。
4. **字体证据**：每个角色使用配置的中文字体，实测字号及字重。保留数学正斜体/上下标。不因“看起来差不多”替换黑体为伪粗宋体。缺少期刊明确规范时如实标为自定默认。

`review.json` 是真实审查记录，不是要求机器制造一份全绿证明。自动检查不能核实审校者是否真的看过；最终报告必须区分脚本通过与人工/智能体查看。未获独立代理时记录 `serial-self-review`，不能称独立双人审校。

先审校再修订；修订后的内容重新绑定哈希并核查受影响页。技术门槛失败最多做三轮针对性修复；同类问题持续失败就换 routes 中的备选，保留失败记录，避免无界循环。
