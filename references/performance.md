# PDF 打开、翻页和滚动卡顿

## 区分根因

| 证据 | 常见机制 | 处理 |
|---|---|---|
| 首次加载慢、完整中文字库很大 | 字体未子集化，解析成本高 | 有界子集化，保持字形和文字提取 |
| 每页数百至上千个 Contents | 每字/小片段各写一个流 | 按原顺序无损串接，不改变绘制内容 |
| PDF 不大却每页数万/数十万条指令、文字层远多于可见正文 | 每个裁切公式/题录片段仍携带完整源页 | 在各 Form 自己的坐标系清理确定不可见内容，保留 BBox/Matrix 并逐对象验证 |

`show_pdf_page(..., clip=...)` 只保证显示裁切，不保证裁切外的源文字/图形被物理删除。逐字符流碎片和重复裁切源页是不同负担；原位版和阅读版要分别测量。压缩率不是性能验收指标。

## 工具与步骤

1. 保留原文件并记录哈希、页数、Contents/Form 数与字体大小。同倍率测首页、公式密集页、图文页和题录页，再测整篇；分别记录解析、绘制及文字层时间。多轮测量控制缓存，避免并行 CPU 争用。
2. `python -m pip install -r requirements-performance.txt`。该路线需要支持 `clip_to_rect` 的 PyMuPDF，不要求重新 OCR 或翻译。
3. 另存原生矢量候选：

```text
python scripts/pdf_optimize.py INPUT.pdf OUTPUT_流畅版.pdf --timeout 300
```

脚本在每个独立 Form 的局部坐标系清理不可见内容；保留 2pt 清理保护带，**不扩大原 Form 的最终可见边界**。候选 Form 先核对原生文字与局部多倍率像素，失败恢复该对象，共享根 Form 保守保留。再无损合并 Contents、子集化字体、压缩保存，不使用可能卡住的 `garbage=4`。

worker 限时；异常只留证据，不覆盖原件。只做流合并/字体时用 `--no-prune`；仅字体步骤异常可测试 `--no-subset`，仍过全部门槛。加密、签名、带标签结构、可选内容层或旋转页需要明确适配，不能丢掉这些结构来通过。

4. 所有页核对指定倍率像素、原生文字、尺寸/页数、元数据、链接及书签；通过才写输出。`OUTPUT_流畅版.performance.json` 记录逐对象采用/回退和逐页证据。像素等价结论限于记录的 MuPDF 版本与倍率，不外推所有查看器。
5. 用独立内核（如 Poppler/PDF.js）复查。少量裁切边界抗锯齿像素可能不同：定位原对象、放大核对、如实记录；不能仅因面积小自动批准。出现字符、公式、图形损失、位移或颜色变化则恢复原对象。严格要求跨内核逐像素一致时保留相关对象或退回仅合并模式，再实测性能。
6. 同一查看器、缩放、窗口和缓存条件下测试新命名文件，检查滚动、搜索、复制、书签、链接和批注。区分库级基准和真实应用体感，不把 Node 时间称作 Zotero/WPS FPS。

## 可选 PDF.js 基准

`scripts/pdfjs_benchmark.mjs` 使用已存在的 `pdfjs-dist` 及其可解析到的 `@napi-rs/canvas`；它们只用于测量，优化器不依赖 Node。本工具不安装依赖、不上传 PDF。

```text
node scripts/pdfjs_benchmark.mjs INPUT.pdf benchmark.json --pdfjs-root /absolute/path/to/node_modules/pdfjs-dist --pages 1,3,6,10 --scale 2 --runs 3
```

报告每轮/页的解析、Canvas 绘制、文字层提取时间与操作数；`--png-dir NEW_DIR` 保存首轮图像。写明版本、倍率、轮次、选页；比较相同页，不能只挑提速最大的页。整篇测量可列出全部页码。

## Cox 2021 实测经验

原位版：Contents 总数 2396→21，xref 对象 2728→353，28,481,815→5,490,444 字节。主要改善首次中文字体解析，Canvas 绘制没有数量级变化。

阅读版：Contents 16019→19，xref 对象 17381→3001；1015 个根 Form 中 987 个清理、28 个保留；9,783,466→7,135,284 字节。PDF.js 5.6.205、2× Canvas、三轮整篇19页，逐页取中位数再跨页平均：

| 指标 | 前 | 后 |
|---|---:|---:|
| 每页解析＋绘制＋文字层 | 2615ms | 342ms |
| 最慢页总处理 | 6465ms | 1513ms |
| 全篇绘制指令 | 1,798,044 | 223,156 |
| PDF.js 文字层字符（含裁切隐藏内容） | 4,122,841 | 147,988 |

原位版同口径平均162→134ms、最慢541→348ms。此机器 Zotero 捆绑 PDF.js 5.7.0；以上是同系列库基准，不是应用内 FPS。

两版共40页在 MuPDF 144/216 DPI 的像素、原生文字、书签、链接和元数据核对通过。PDF.js 中原位版逐像素相同；阅读版约0.0047%像素有差异，主要在重复裁切边缘，需定位与放大复核，不称所有内核逐像素一致。未采用整页图片化或 OCR 重写，正文、数学及图形保留原生对象；本案例不构成任意论文的速度承诺。
